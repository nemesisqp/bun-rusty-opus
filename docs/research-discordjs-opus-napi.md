# Research: @discordjs/opus + napi-rs prebuilt distribution

Source: research subagent, 2026-11-13. Verified against @discordjs/opus README / napi-rs docs.

## @discordjs/opus API (mirror this shape)

- Current version 0.10.0 (Jan 2025), "Native bindings to libopus v1.3", Node >=12.
- Single export, no separate OpusDecoder: `const { OpusEncoder } = require('@discordjs/opus')`
- `new OpusEncoder(48000, 2)` — defaults 48000 Hz, 2 channels. Throws on unsupported rate.
- `encode(buf, frameSize?)` — s16le interleaved PCM Buffer in, Opus Buffer out. frameSize = samples per channel; inferred from `buf.length / (channels * 2)`.
- `decode(buf, frameSize?)` — Opus Buffer in, PCM Buffer out.
- `setBitrate(bitrate)` / `getBitrate()`, `setFEC(enabled)`, `setPLP(percentage 0-100)`,
  `applyEncoderCTL(ctl, value)`, `applyDecoderCTL(ctl, value)` — raw opus_*_ctl passthrough.
- Rates: only 8000, 12000, 16000, 24000, 48000. Channels: 1 or 2.
- Frame durations: 2.5, 5, 10, 20, 40, 60 ms → at 48kHz: 120, 240, 480, 960, 1920, 2880 samples/channel.
- Discord standard: 48kHz stereo 20ms = 960 samples → PCM frame 960*2*2 = 3840 bytes.
- discord.js voice uses it indirectly via prism-media (`prism.opus.Encoder/Decoder`), which loads
  @discordjs/opus and falls back to opusscript if absent. A drop-in replacement must satisfy
  prism-media's loader, i.e. the OpusEncoder shape above.
- Platforms claimed: Linux x64/ia32/arm/arm64, macOS x64/arm64, Windows x64.

## How @discordjs/opus distributes prebuilds — DO NOT copy

- @discordjs/node-pre-gyp fork, binding.gyp, bundled C source in deps/opus/, src/ C++ N-API.
- Install = `node-pre-gyp install --fallback-to-build`. Release assets named like
  `opus-v0.9.0-node-v108-napi-v3-linux-x64-glibc-2.40.tar.gz` at
  github.com/discordjs/opus/releases/download/v<version>/
- Failure mode: exact node-vNN / glibc combo missing (404) → silently falls back to node-gyp
  source compile (needs Python + C++ toolchain), then fails obscurely. This is exactly what
  bun-rusty-opus must avoid: no node-pre-gyp, no prebuildify, no binding.gyp, no install/postinstall fallback.

## napi-rs prebuilt-only pattern (use this)

- Scaffold: `npx @napi-rs/cli new` / template napi-rs/package-template. CLI v3 renamed
  `napi.triples` → `napi.targets`, `name` → `binaryName`, `create-npm-dir` → `create-npm-dirs`.
  Do not commit `npm/*` — generate it in CI with `napi create-npm-dirs`.
- Layout:
  ```
  package.json  # "napi": { "binaryName": "bun-rusty-opus", "targets": [...] }
                # "main": "index.js", "types": "index.d.ts"
  index.js      # generated loader
  index.d.ts    # generated by napi build
  Cargo.toml    # cdylib crate; build.rs: napi_build::setup();
  npm/darwin-x64/package.json  # { "name": "<pkg>-darwin-x64", "os": ["darwin"], "cpu": ["x64"], ... }
  npm/darwin-arm64/ npm/linux-x64-gnu/ npm/linux-x64-musl/
  npm/linux-arm64-gnu/ npm/linux-arm64-musl/
  npm/win32-x64-msvc/ npm/win32-arm64-msvc/
  # each contains exactly one file: bun-rusty-opus.<platform>.node
  ```
- Main package lists every platform package in `optionalDependencies` with lockstep version.
  Each platform package.json declares os/cpu (Linux gnu vs musl via suffix), so npm/bun install
  only the matching one and silently skip the rest.
- `napi build --platform --release` produces `<binaryName>.<platform>.node`.
  `napi prepublish` / `napi publish` generates optionalDependencies + per-platform packages.
- Loader (index.js, generated): switches on process.platform/arch; on Linux tries -gnu then -musl;
  first tries local `./<name>.<platform>.node` (dev build), then `require('<pkg>-<platform>')`.
  On failure throws `Unsupported OS: ...` / `Failed to load native binding`. No build fallback.
- Prebuilt-only enforcement: (a) no install/postinstall script, no binding.gyp, no Rust source
  shipped as build fallback; (b) customise loader's final error to name package, detected
  platform-arch-libc, and supported list; (c) consequence: platform packages are *optional*, so
  npm/bun install succeeds silently when no binary matches — failure surfaces only at
  require()/import time, so the loader error message is the whole UX; (d) publish ALL platform
  packages on every release, names exactly matching what the loader requires.
- Naming warning: napi-rs recommends a scoped main package, because unscoped platform packages
  like `bun-rusty-opus-linux-x64-gnu` can trip npm spam detection. If public name must stay
  unscoped `bun-rusty-opus`, publish platform packages under a scope via
  `napi build --js-package-name @<scope>/bun-rusty-opus` (snappy precedent).
- Bun compatibility: Bun loads napi-rs .node files natively via require() (N-API). Sync
  encode/decode is the safe surface; async/threadsafe-function N-API paths had Bun crashes
  fixed only in Bun 1.3.14, so test on recent Bun and Node 20/22/24.

## Recommended CI matrix

Minimum 8-target set covering "most platforms" (defer armv7, freebsd, android, wasm):

| Host | Target triple | npm suffix |
|---|---|---|
| macos-latest | x86_64-apple-darwin | darwin-x64 |
| macos-latest | aarch64-apple-darwin | darwin-arm64 |
| windows-latest | x86_64-pc-windows-msvc | win32-x64-msvc |
| windows-latest | aarch64-pc-windows-msvc | win32-arm64-msvc |
| ubuntu-latest | x86_64-unknown-linux-gnu | linux-x64-gnu |
| ubuntu-latest | x86_64-unknown-linux-musl | linux-x64-musl |
| ubuntu-latest | aarch64-unknown-linux-gnu | linux-arm64-gnu |
| ubuntu-latest | aarch64-unknown-linux-musl | linux-arm64-musl |

Supporting jobs: fmt (`cargo fmt --check`), clippy `-- -D warnings`, `cargo test` on
ubuntu/macos/windows, binding tests on Node 20/22/24, Swatinem/rust-cache@v2, mlugg/setup-zig +
taiki-e/install-action (cargo-zigbuild) for Linux cross jobs. Build Linux-gnu in an old
container (ghcr.io/napi-rs/napi-rs/nodejs-rust:lts-debian / ubuntu:20.04) to keep glibc
baseline low — @discordjs/opus 404s were precisely glibc-version mismatches.
Publish (main + all platform packages, `npm publish --provenance`) only on semver tags.
